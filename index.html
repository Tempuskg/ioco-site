Find the code behind your ASP.NET Core URLs.

Review changes with the relevant files in view. Analysis stays on your machine.

IOCO maps a .NET solution by what its users see: every URL of an ASP.NET Core app, every menu item of a WinForms or WPF app, every command of a console app. Under each one it lists the files that serve it, and why each file is there. It reads source with Roslyn and needs no build, so it also works on code that doesn't compile. It doesn't move or change any file.

A pull request changes the shared SmtpEmailSender. ioco review turns the Git diff into candidate URLs to review, with the relationship behind each one:

These are candidates to review, not proof of runtime impact. An unlisted URL can still be affected, and the report says so. --format markdown or --format html writes the same review as a file you can attach to the pull request.

The outputs above come from the tutorial sample and are checked by IOCO's test suite.

Install and get your first map

One product with three integrations. They share the same analysis engine and the same license.

VS Code Preview

  1. Install the .NET 8 runtime or later. The SDK is not needed.
  2. Install IOCO View: . The extension bundles the IOCO CLI.
  3. Open a folder with your solution. IOCO maps a single .sln automatically. Otherwise, run IOCO: Choose Solution….
  4. Open the IOCO view in the Explorer.

Validated on local Windows x64 with VS Code 1.140.0 and 1.142.0. macOS, Linux, ARM64 and remote (SSH, container, WSL) hosts are not validated yet.

Visual Studio Preview

  1. Install IOCO View: .
  2. Open your solution, then View > Other Windows > IOCO.
  3. The tool window maps the open solution, in process.

The IOCO window has been checked on Visual Studio Community 2022 17.14.25 and Community 2026 18.10.3 (Windows x64). Visual Studio 2022 17.9, Professional/Enterprise, ARM64 and a clean-machine install are not validated yet.

Command line Preview

  1. Install the .NET 8 SDK or later. Installing a .NET tool needs the SDK.
  2. : dotnet tool install --global Ioco.Cli --add-source <folder with the .nupkg>
  3. ioco map path/to/YourApp.sln, or add --json for the JSON map.

The JSON output follows a versioned contract and is free to use in your own tools.

Supported patterns

IOCO picks an organizer for each project from its project file. A solution can mix organizers, and each one gets its own tree. Libraries appear through the entries that use them.

ProjectWhat is mapped
ASP.NET Core (C#)MVC controllers with attribute routes ([Route], [HttpGet("…")], [controller]/[action]/[area] tokens) and conventional routes (MapControllerRoute, MapDefaultControllerRoute, MapAreaControllerRoute); Razor Pages with handlers; minimal APIs including nested MapGroup prefixes. For each endpoint: views and partials (resolved through ASP.NET Core's default locations), models and page models, and injected services with their DI-registered implementations, to a depth you choose.
WinForms (C# and Visual Basic)MenuStrip/ToolStripMenuItem and MainMenu/MenuItem, from the designer or code, with text from code or .resx; toolbar buttons and context menus; for an app without a menu, its startup form and the forms reachable from it.
WPF (C#)XAML Menu/MenuItem with Click handlers, view-model commands (RelayCommand, DelegateCommand, CommunityToolkit [RelayCommand], custom ICommand) and routed commands; toolbars, context menus and System.Windows.Controls.Ribbon; windows for an app without a menu.
Console (C#)System.CommandLine, Spectre.Console.Cli, CommandLineParser, McMaster.Extensions.CommandLineUtils, Cocona and ConsoleAppFramework commands, plus hand-written dispatch on args.

Known limits

  • Routes must be constant strings. Custom route conventions, AddPageRoute, a custom Razor Pages root and custom view location expanders are not modelled.
  • Compile Remove/Include, conditional properties and Directory.Build.props are ignored; sources come from the SDK's default globs.
  • Layouts and view components are not listed as serving files. Third-party ribbons and menus built at run time are not mapped.
  • Visual Basic WPF, web and console projects are loaded but not mapped. F# projects are skipped.
  • A file relationship is not proof of runtime impact, and an empty lookup does not prove a file has no impact.

Privacy

  • Your code stays on your machine. The editors and the CLI read files locally. They have no telemetry and make no network calls. The VS Code extension starts one local process, the bundled CLI, with .NET telemetry turned off.
  • Licenses are checked offline. The trial and signed license files are validated on your computer. There is no account, and IOCO never contacts a server about your license.
  • Maps and reports stay where you put them. A map shows your application's structure, so treat it like source. Team settings and baselines are ordinary files in your own repository. CI reports should stay in storage you control.
  • Checkout is the only exchange with us. Payment will be handled by a merchant of record, which receives your billing details and never your code. This page loads no analytics, fonts or scripts from other sites.

From a free map to Pro

The trial starts when you choose to start it, not when you install. The upgrade prompt appears when you use a Pro feature. Apart from that, the editors show your license status, and while the trial is unused the VS Code view notes after each map that it is available. Community features never stop to ask you to upgrade.

  1. Install Community and map your solution. Follow the install steps. The trial can only start after one successful map.
  2. Use a Pro feature on your own code. In VS Code, right-click a file and choose Show Candidate Affected Endpoints. In Visual Studio, use Tools > IOCO: Candidate Affected Endpoints. In the CLI, run git diff --name-status main...HEAD | ioco review or ioco compare.
  3. Start the 14-day Pro trial. The editor prompt offers Start 14-day Pro trial, the CLI prints how to start it, and you can run it directly: IOCO: Start 14-day Pro Trial in VS Code, Start 14-day Pro Trial in the Visual Studio IOCO window, or ioco license trial start. You don't need a card or an account. The trial is offered once per person and covers all three integrations.
  4. Get the result. Review the candidate URLs and their reasons, then export a Markdown or HTML review to attach to your pull request.
  5. Buy Pro. After checkout you receive a signed license file for one named user.
  6. Activate the license offline. Run IOCO: Activate Signed License in VS Code, enter the file's path and choose Activate License in the Visual Studio IOCO window, or ioco license activate <file>. All three integrations on your computer use the same license store. IOCO: License Status or ioco license status shows the current state.

You go back to Community. Mapping, navigation and JSON keep working. Reports, exports and baselines you generated are yours to keep, open and share without a key. Only running a Pro workflow again needs a license. Subscriptions have a 7-day renewal grace period.
